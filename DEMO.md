# Three minutes with SONICBRIDGE

Use two visible screens and one short audience-chosen message. A completed physical send has two observable endpoints: a verified receipt on the receiving screen and delivery confirmation on the sending screen.

**Before going on stage.** Load the production build over trusted HTTPS on both devices, grant mic access, wait for **Offline app ready**, and rehearse offline reload, routes and calibration. Keep screens awake. Open the benchmark table from disk. Have a locally stored tiny image and a timer. Record three rehearsal times through FIN_ACK for the exact image, devices and settings in the [physical sheet](PHYSICAL_TEST_SHEET.md). Without these measurements, omit the live image. No physical rehearsal times have been recorded in this release.

| Clock | Action | What the audience can check |
| --- | --- | --- |
| 0:00–0:25 | Load both apps. Show the physical mode label. Disconnect Wi-Fi, cellular and wired networking on both devices, reload from cache, tap **Start Audio** on both, and select **Listen with microphone** on the receiver. Select Adaptive on the sender. | Both interfaces work offline. The receiver shows its actual input and readiness. |
| 0:25–1:15 | Ask for a fresh short random string, e.g. six characters chosen by the audience. Type it after disconnection. Send it. Keep both screens visible. | Compare the received text with the audience’s string. Show receiver SHA-256 verification, then the sender’s FIN_ACK confirmation or its actual pending state. |
| 1:15–1:55 | During an active transfer introduce brief, moderate noise near the receiver, then restore quiet. If the first transfer already finished, send a second fresh short string. Expand **Packet timeline** and **Controller decisions**. | Point to actual missing ACKs, retries or confirmed changes if present. If none appear, say “No retry or mode change observed.” Input amplitude alone cannot identify a lost packet. |
| 1:55–2:30 | Send the tiny image only if the preceding transfer has finished and the slowest measured rehearsal plus a 10 s margin fits before 2:30. Show its encoded byte count before sending. Otherwise use this slot to inspect the text receipt and timeline. | Open the reconstructed image only after verification. Identify any still-pending sender confirmation separately. |
| 2:30–3:00 | Show the verified result actually obtained and the local fixed-versus-adaptive table. Keep any failed or unfinished stage attempt visible or recorded. | Label the table **simulated PCM**. Quiet 480-byte trials averaged 75.2 s Balanced/Adaptive and 85.1 s Robust. All modes failed to complete on both impaired traces. |

**Fallback.** If offline setup or microphone access fails by 0:25, or no physical receipt appears by 1:15, state the observed failure, record the outcome and cancel any active send. Switch visibly to **Simulation · local PCM** on one device, still offline. Send a new audience-chosen text and show the local verified receipt. Explain that both endpoints and the real codec ran on that device. Use the recorded noise-burst rows to discuss retries. If time runs out, show the local ledger and report exactly where the live attempt stopped. [All trials and terminal reasons](BENCHMARKS.md)
